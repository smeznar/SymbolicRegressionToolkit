    Constraints

    SRToolkit.utils.grammar.constraints

    Constraint protocol for grammar-guided expression generation.

    A GrammarConstraint is a hard filter: at each derivation step its allows method decides which candidate rules survive.

    All constraints operate on an ExpansionContext view that exposes the current derivation position together with the constraint's own per-slot local state.

    Per-derivation state comes in two flavours:

    • Local — per-slot, inherited from parent to children. The engine maintains a stack parallel to the open frontier; each constraint sees only its own local value for the current slot.
    • Global — per-derivation scalar, lives on the engine alongside the frontier. Suitable for counters and accumulators.

    Both flavours are owned by the engine; the Derivation initialises them at Grammar.start_derivation and threads them through every allows / update call. GrammarConstraint instances carry only construction-time configuration and are safe to share across parallel derivations.

    Built-in constraints

    • MaxDepth: limit on the derivation depth
    • MaxNodes: limit on the number of rule applications
    • MaxOccurrences: limit on how often a terminal occurs
    • NoNested: no symbol of a group nested inside one of the group
    • DimensionalConsistency: units consistent and equal to the target's

    GrammarConstraint

    Bases: Generic[L, G]

    Base class for derivation constraints (hard filters).

    Subclass and override the methods you need. Constraints carry only construction-time configuration; all per-derivation state is managed by the engine and threaded through method arguments.

    Scoping — set nonterminals and/or rule_names to restrict allows to a subset of slots or rules. A scope miss is treated as implicit acceptance. update is always called regardless of scope so that global counters stay accurate.

    Examples:

    >>> from SRToolkit.utils.grammar import Grammar, Rule
>>> g = Grammar([Rule("E", ["x"]), Rule("E", ["y"])])
>>> class RejectY(GrammarConstraint):
...     def allows(self, slot, rule, global_): return rule.rhs != ["y"]
>>> g.add_constraint(RejectY())
>>> d = g.start_derivation("E")
>>> [r.rhs for r in d.options()]
[['x']]

    def to_dict(self) -> dict:
    """Serialise this constraint to a JSON-safe dictionary.

    The base implementation stores only the fully-qualified class path under
    ``constraint_class``. Subclasses should call ``super().to_dict()`` and
    add their own constructor arguments so that ``from_dict`` can reconstruct

    Returns:

    from_dict classmethod 

    from_dict(d: dict) -> 'GrammarConstraint'

    Reconstruct a constraint from a dictionary produced by to_dict.

    When called on the base GrammarConstraint class, dispatches to the correct subclass via the constraint_class key using importlib — both built-in and user-defined subclasses are supported. When called on a concrete subclass, the subclass must override this method.

    The dictionary must contain at minimum the key constraint_class, whose value is the fully-qualified class path (e.g. "mymodule.MyConstraint"). Any additional keys are forwarded to the subclass override.

    To make a custom subclass serialisable, override both to_dict and from_dict::

    class MyConstraint(GrammarConstraint):
    def __init__(self, threshold: float) -> None:
        self.threshold = threshold

    def to_dict(self) -> dict:
        return {**super().to_dict(), "threshold": self.threshold}

    @classmethod
    def from_dict(cls, d: dict) -> "MyConstraint":
        return cls(d["threshold"])

    Examples:

    >>> from SRToolkit.utils.grammar import GrammarConstraint, MaxDepth
>>> c = GrammarConstraint.from_dict(MaxDepth(5).to_dict())
>>> isinstance(c, MaxDepth) and c.limit == 5
True

def from_dict(cls, d: dict) -> "GrammarConstraint":
    """Reconstruct a constraint from a dictionary produced by ``to_dict``.

    When called on the base [GrammarConstraint][SRToolkit.utils.grammar.constraints.GrammarConstraint]
    class, dispatches to the correct subclass via the ``constraint_class`` key using
    `importlib` — both built-in and user-defined subclasses are supported.
    When called on a concrete subclass, the subclass must override this method.

    The dictionary must contain at minimum the key ``constraint_class``, whose value
    is the fully-qualified class path (e.g. ``"mymodule.MyConstraint"``).  Any
    additional keys are forwarded to the subclass override.

    To make a custom subclass serialisable, override both ``to_dict`` and
    ``from_dict``::

        class MyConstraint(GrammarConstraint):
            def __init__(self, threshold: float) -> None:
                self.threshold = threshold

            def to_dict(self) -> dict:
                return {**super().to_dict(), "threshold": self.threshold}

            @classmethod
            def from_dict(cls, d: dict) -> "MyConstraint":
                return cls(d["threshold"])

    Examples:
        >>> from SRToolkit.utils.grammar import GrammarConstraint, MaxDepth
        >>> c = GrammarConstraint.from_dict(MaxDepth(5).to_dict())
        >>> isinstance(c, MaxDepth) and c.limit == 5
        True

    Args:
        d: Dictionary previously returned by ``to_dict``.

    Returns:
        A reconstructed [GrammarConstraint][SRToolkit.utils.grammar.constraints.GrammarConstraint] instance.

    Raises:
        KeyError: If ``constraint_class`` is missing from ``d`` (dispatch path).
        ImportError: If the module cannot be imported (dispatch path).
        AttributeError: If the class cannot be found in the module (dispatch path).
        NotImplementedError: If called on a subclass that has not overridden this method.
    """
    if cls is GrammarConstraint:
        d = _auto_bind(d)
        class_path = d["constraint_class"]
        module_path, cls_name = class_path.rsplit(".", 1)
        try:
            resolved = getattr(importlib.import_module(module_path), cls_name)
        except (ImportError, AttributeError):
            raise ImportError(
                f"Cannot import constraint class {class_path!r}. "
                "If this is a bundle class, install the bundle first. "
                "If the config has no '_bundle' key, call bind_config(config) manually."
            ) from None
        return resolved.from_dict(d)
    raise NotImplementedError(f"{cls.__name__}.from_dict is not implemented.")

    def update(self, slot: ExpansionContext[L], rule: Rule, global_: G) -> tuple[list[L], G]:
    """Called after ``rule`` is applied at ``slot``.

    Returns per-child local states (one per non-terminal in ``rule.rhs``,
    in order) and the new global state. May be used to update global
    counters by returning a new ``global_`` value.

    Args:
        slot: Derivation position immediately before the rule was applied.
        rule: The rule that was applied.
        global_: Global state before this application.

    Returns:
        ``(child_locals, new_global)`` where ``len(child_locals)`` equals
        the number of non-terminals in ``rule.rhs``.
    """
    n = sum(1 for s in rule.rhs if s in slot.nonterminals)
    return [slot.local] * n, global_

    MaxDepth 

    MaxDepth(limit: int)

    Bases: GrammarConstraint[int, None]

    Hard limit on derivation depth.

    Local state is the remaining depth budget at each slot. A rule is rejected when its application would require at least one recursive non-terminal child but the budget has reached zero.

    Examples:

    >>> from SRToolkit.utils.grammar import Grammar, Rule
>>> g = Grammar([
...     Rule("E", ["E", "+", "E"]),
...     Rule("E", ["x"]),
... ])
>>> g.add_constraint(MaxDepth(0))
>>> d = g.start_derivation("E")
>>> all(r.rhs == ["x"] for r in d.options())
True

    def allows(self, slot: ExpansionContext[int], rule: Rule, global_: None) -> bool:
    if slot.local <= 0:
        has_nt = any(s in slot.nonterminals for s in rule.rhs)
        return not has_nt
    return True

    MaxNodes 

    MaxNodes(limit: int)

    Bases: GrammarConstraint[None, int]

    Hard limit on the total number of rule applications in a derivation.

    Global state is a running count of applications so far. A rule is rejected when applying it would push the count over the limit taking into account the non-terminal children it introduces (each of which will require at least one more application).

    Examples:

    >>> from SRToolkit.utils.grammar import Grammar, Rule
>>> g = Grammar([
...     Rule("E", ["E", "+", "E"]),
...     Rule("E", ["x"]),
... ])
>>> g.add_constraint(MaxNodes(3))
>>> d = g.start_derivation("E")
>>> # At node-count 3 only the terminal rule survives
>>> tokens = d.generate()
>>> len(tokens) <= 5
True

    NoNested 

    NoNested(symbols: str | Iterable[str])

    Bases: GrammarConstraint[bool, None]

    Prevent any symbol in a group from appearing nested inside a symbol of the group.

    The same symbol counts: NoNested("sin") forbids sin(sin(x)).

    Local state is a boolean "currently under any symbol in the group". Any rule whose rhs contains a group symbol is rejected while the local state is True. Children inherit True once such a rule is applied.

    Pass a single string to forbid self-nesting only; pass multiple symbols to forbid cross-nesting within the group (e.g. NoNested(TRIG_FNS) prevents sin(cos(x)) as well as sin(sin(x))).

    Warning

    This constraint propagates the "inside" flag to all non-terminal children of any rule whose rhs contains a group symbol. It works correctly when each group symbol appears in a rule with exactly one non-terminal child (typical prefix-function rules such as E -> sin ( E )) and for infix operators where every child should be blocked (e.g. E -> E + E). It does not work correctly for mixed rules that combine a function call with additional non-terminal siblings in a single production (e.g. E -> sin ( E ) + F): the sibling F will be incorrectly treated as inside the group. If your grammar uses such rules, implement a custom GrammarConstraint instead.

    Examples:

    >>> from SRToolkit.utils.grammar import Grammar, Rule
>>> g = Grammar([
...     Rule("E", ["sin", "(", "E", ")"]),
...     Rule("E", ["cos", "(", "E", ")"]),
...     Rule("E", ["x"]),
... ])
>>> g.add_constraint(NoNested(["sin", "cos"]))
>>> d = g.start_derivation("E")
>>> d.apply(g.rules_for("E")[0])   # apply sin(E)

    DimensionalConsistency 

    DimensionalConsistency(variable_units: Mapping[str, Unit], target_unit: Unit, symbol_library: SymbolLibrary, literal_units: Optional[Mapping[str, Unit]] = None)

    Bases: GrammarConstraint[Any, None]

    Generate only expressions whose units are consistent and equal to the target's.

    Prunes a grammar's derivations so that every expression it completes passes ConsistentUnits with the same units: variables and named constants ("lit" symbols) have the given units; free constants, numbers and literals without a unit are dimensionless. How an operator or function combines units is its UnitRule in symbol_library. This holds for grammars whose parse tree is the tree of the emitted expression, as with Grammar.from_symbol_library; with an ambiguous grammar such as E -> E + E | E * E the emitted tokens can parse to a different tree.

    Supported grammars. A rule's role comes from its terminals, brackets ignored:

    • one "op" or "fn" terminal, with as many non-terminals as its unit rule accepts: that unit rule;
    • no terminals and one non-terminal (E -> F, R -> ( E )): the requirement passes on;
    • one leaf terminal (a variable, literal, "const" symbol, or a number: any token float() accepts) and no non-terminals: a leaf, with the unit above.

    Any other rule, e.g. E -> E + C or one with a terminal that is not a library symbol, bracket or number, raises ValueError naming the rule when it is a candidate in a derivation; Grammar.generate_one does not catch it.

    Required units. Each open slot has a required unit, or "any": the slot may take any unit, but its subtree must still have no conflict as ConsistentUnits counts them. The start slot requires target_unit. A slot with required unit P rejects a leaf whose unit is not P, and a rule whose result is dimensionless (EXPONENT, DIMENSIONLESS, power(0)) if P is not dimensionless. Every other rule fits; any rule fits an any slot. The children of a rule with unit rule r must have these units, the second one decided when it is expanded, from the finished first child's unit U (the derivation is leftmost):

    r first child second child
    SAME P U
    MULTIPLY any P / U
    DIVIDE any U / P
    power(k) P ** (1/k); any for power(0)
    DIMENSIONLESS dimensionless dimensionless
    EXPONENT dimensionless dimensionless

    Where P is any, a child given as P, P / U, U / P or P ** (1/k) is any too. EXPONENT (the ^ operator) is stricter here than in ConsistentUnits: a dimensional base raised to a number (X_0 ^ 2) is never generated, even though ConsistentUnits accepts it; postfix powers such as ^2 cover it.

    Dead ends. A required unit can turn out impossible once the first child is finished (e.g. the second factor would need m^3 but the depth limit leaves only a leaf). The slot then has no allowed rule: Derivation.generate raises RuntimeError, and generate_one starts again and returns None if every attempt fails. With tight units or depth limits, raise its max_retries.

    Warning

    Generation is slow for target units that are products of several dimensions. The first factor of a product is chosen without knowing whether the second can still reach the required unit, so most derivations end in a dead end. With Grammar.from_symbol_library and variables X_0 in m and X_1 in s, about a third of the derivations succeed for target m, about one in seven for a dimensionless target, 1–2 % for m s^-1, and 0.3 % or less for m^2 s and for m^-2 when both variables are in m. Every generated expression is correct; only the success rate is low. Raise max_retries or give the grammar fewer choices.

    def allows(self, slot: ExpansionContext[Any], rule: Rule, global_: None) -> bool:
    """Return whether ``rule`` fits the slot's required unit (see the class docstring).

    Returns:
        ``True`` if the rule fits.

    Raises:
        ValueError: If ``rule`` has a shape the constraint does not support (see "Supported

            child's tokens parse to a tree with a unit conflict.

        return shape == required
    if shape in (UnitRule.EXPONENT, UnitRule.DIMENSIONLESS) or shape.exponent == 0:
        return required == _DIMENSIONLESS
    return True

    def update(self, slot: ExpansionContext[Any], rule: Rule, global_: None) -> tuple[list[Any], None]:
    required = self._required(slot)
    shape = self._shape(rule, slot.nonterminals)
    if isinstance(shape, Unit):  # a leaf
        return [], None
    if shape is None:  # pass-through
        return [required], None
    n = sum(1 for s in rule.rhs if s in slot.nonterminals)
    if shape == UnitRule.SAME:  # the second operand needs the first one's unit; no parent needed
        return ([required] if n == 1 else [required, _Second(shape, None)]), None
    if shape in (UnitRule.MULTIPLY, UnitRule.DIVIDE):
        return [None, _Second(shape, required)], None
    if shape.exponent is not None:  # power(k)
        if shape.exponent == 0 or required is None:
            return [None], None
        return [required ** (1 / shape.exponent)], None
    return [_DIMENSIONLESS] * n, None  # DIMENSIONLESS, EXPONENT
