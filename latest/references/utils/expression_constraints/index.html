    Expression constraints

    SRToolkit.utils.expression_constraints

    Constraints that a candidate expression must, or should, satisfy.

    An ExpressionConstraint checks a candidate expression at one or both of two points of its evaluation:

    • pre_check looks at the expression itself, before it is scored: its length, its symbols, its structure. It reads no data.
    • post_check looks at the scored model, a ModelResult with the fitted parameters, e.g. to require that the fitted model's output stays non-negative.

    A constraint implements one of the checks or both. A check it does not implement keeps the base class's default, which returns a CheckResult with implemented=False; the evaluator skips it. Each check returns whether the expression passed, a short message, and an amount saying how far outside the constraint it is (e.g. 3 for three tokens too many). Amounts of different constraints are in different units and are not comparable.

    Data and setup

    A constraint receives the data it owns at construction (limits, units, evaluation points), and saves it with to_dict. The context it shares with the evaluator, the symbol library, comes through setup and is not saved. The SR_evaluator calls setup in its constructor, on its own shallow copies of the constraints, so the same instance can be given to evaluators with different symbol libraries. Every built-in constraint needs the library: to use one on its own, call setup first, or its checks raise RuntimeError. A custom constraint that does not need the library can be used without setup.

    Required and advisory constraints

    The same constraint can play two roles; the evaluator list it is registered in decides which:

    • Required constraints belong to the objective (required_constraints). An expression that fails one gets the status "rejected" and the error +inf. Use them for restrictions every approach must respect, e.g. to compare approaches on the same search space.
    • Advisory constraints describe the search space the task suggests (advisory_constraints). An approach may use them or ignore them. The evaluator records each failed advisory check in ModelResult.advisory_violations but does not change the score.

    Penalties are not part of the evaluator: a custom RankingFunction can hold constraints and combine their amounts into its score.

    Input forms of pre_check

    pre_check accepts a token list or a Node tree, and each constraint converts it to the form it needs: constraints that look at the tree parse a token list with tokens_to_tree; constraints that count tokens write a tree out with Node.to_list. A tree has no unique token list: to_list places only the brackets that are needed, so a tree can have fewer tokens than a token list with redundant brackets for the same expression. The evaluator always passes the token list it stores as ModelResult.expr, so a saved result re-checks to the same verdict.

    The expression must be well-formed. For a malformed token list, constraints that parse it raise ExpressionParseError, while constraints that only look at tokens give a result without noticing. The evaluator parses every expression before checking it, so this cannot happen there.

    Error messages

    The ValueError and RuntimeError messages of the built-in constraints start with the constraint's class name (e.g. "MaxTokens: the limit must be a non-negative int, got -1."), so an error raised while a dataset or an evaluator is built says which constraint caused it.

    Built-in constraints

    Constraint Check Fails when
    MaxConstants pre more free constants (tokens of type "const") than the limit
    MaxTokens pre more infix tokens, brackets included, than the limit
    MaxTreeDepth pre the tree is higher than the limit (a single leaf has height 1)
    MaxTreeSize pre the tree has more nodes than the limit
    RequiredVariables pre a required variable does not occur
    MaxSymbolCount pre a symbol, or a group of symbols together, occurs more often than the limit
    NoNesting pre a symbol of a group occurs below a symbol of the group, the same symbol included
    OutputBounds post the fitted model's output leaves the bounds at one of the given points

    Expression constraints are separate from the GrammarConstraints that prune a grammar's derivations: an expression constraint checks a finished expression and is part of the task, a grammar constraint is a tool of an approach that generates expressions from a grammar.

    Writing your own constraint

    Subclass ExpressionConstraint and implement pre_check, post_check or both. To save it with a dataset or an experiment, also override to_dict and from_dict, as the built-in constraints do: see MaxSymbolCount for plain arguments and OutputBounds for an array, saved through serialization:

    from SRToolkit.utils.expression_constraints import ExpressionConstraint
from SRToolkit.utils.types import CheckResult


class ForbidSymbol(ExpressionConstraint):
    def __init__(self, symbol: str) -> None:
        self.symbol = symbol

    def pre_check(self, expr):
        tokens = expr if isinstance(expr, list) else expr.to_list(self.symbol_library)  # set by setup
        n = tokens.count(self.symbol)
        if n == 0:
            return CheckResult()
        return CheckResult(passed=False, message=f"uses {self.symbol!r}", amount=n)

    def to_dict(self):
        return {**super().to_dict(), "symbol": self.symbol}

    @classmethod
    def from_dict(cls, d):
        return cls(d["symbol"])

    The saved form is {"constraint_class": "<module>.<ClassName>", ...}, where the remaining keys are the constructor arguments; the symbol library is not saved. from_dict imports the class by that path, so user-defined constraints load without being registered anywhere. The class must therefore be importable by that path: define it at module level in an importable module, not inside of __main__, a notebook or a function.

    """Rebuild a constraint from the output of ``to_dict``.

    Called on the base class, it imports the class named by ``d["constraint_class"]`` and calls
    that class's ``from_dict``, so built-in and user-defined constraints load the same way.
    Called on a subclass, the subclass must override it. The rebuilt constraint is not set up.

    Args:
        d: A dictionary produced by ``to_dict``, possibly after a JSON round trip.

    Returns:
        The rebuilt constraint.

    Raises:
        KeyError: If ``d`` has no ``"constraint_class"`` (called on the base class).
        ImportError: If the named class cannot be imported (called on the base class).
        TypeError: If the named class is not an
            [ExpressionConstraint][SRToolkit.utils.expression_constraints.ExpressionConstraint],
            e.g. the grammar-only [MaxNodes][SRToolkit.utils.grammar.constraints.MaxNodes]
            (called on the base class).
        NotImplementedError: If called on a subclass that does not override it, or if the named
            class does not override it.

    Examples:
        >>> c = ExpressionConstraint.from_dict(MaxTokens(20).to_dict())
        >>> type(c).__name__, c.limit
        ('MaxTokens', 20)
    """
    if cls is ExpressionConstraint:
        resolved, d = _resolve_constraint_class(d)
        if resolved is ExpressionConstraint:
            raise NotImplementedError("ExpressionConstraint.from_dict cannot rebuild the base class.")
        return resolved.from_dict(d)
    raise NotImplementedError(f"{cls.__name__}.from_dict is not implemented.")

    def post_check(self, model: ModelResult) -> CheckResult:

        model: The scored model; its ``expr`` and ``parameters`` are used.

        its interval (``inf`` if an output is not finite) and the message
        ``"output outside [<lower>, <upper>] at <k> of <n> points"`` if neither stored bound
        is an array (an array infinite everywhere is stored as ``None``; the bounds formatted with ``str(float(...))``, a missing bound shown as ``-inf``
        / ``inf``), else ``"output outside the bounds at <k> of <n> points"``. If the expression has free constants and ``model.parameters`` is ``None``,
        failed with the message ``"no fitted parameters"``. If ``model.parameters`` is not
        ``None`` and its length differs from the number of free constants (also for a
        constant-free expression, where ``None`` and an empty array pass), failed with
        ``"<n> fitted parameters, expression has <m> constants"``. ``amount = inf`` in both
        cases.

    Raises:
        RuntimeError: If [setup][SRToolkit.utils.expression_constraints.ExpressionConstraint.setup]
            has not been called.
    """
    symbol_library = _require_setup(self)
    output = _predict(model, self.points, symbol_library)
    if isinstance(output, str):
        return CheckResult(passed=False, message=output, amount=float("inf"))
    lower = -np.inf if self.lower is None else self.lower
    upper = np.inf if self.upper is None else self.upper
    finite = np.isfinite(output)
    outside = ~finite | (output < lower) | (output > upper)
    n_outside = int(np.count_nonzero(outside))
    if n_outside == 0:
        return CheckResult()
    if not np.all(finite):
        amount = float("inf")
    else:
        amount = float(np.max(np.maximum(lower - output, output - upper)[outside]))
    where = f"at {n_outside} of {output.shape[0]} points"
    if np.ndim(lower) == 0 and np.ndim(upper) == 0:
        message = f"output outside [{float(lower)}, {float(upper)}] {where}"
    else:
        message = f"output outside the bounds {where}"
    return CheckResult(passed=False, message=message, amount=amount)
