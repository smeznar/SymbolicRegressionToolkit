    SR Evaluator

    SRToolkit.evaluation.sr_evaluator

    Expression evaluation and results management for symbolic regression.

    Contains SR_evaluator, which ranks expressions with a RankingFunction (RMSE by default); SR_results, a container for experiment results; and ResultAugmenter, the base class for post-processing results.

    Evaluation statuses

    Each evaluated expression gets a Status and, unless it is "ok", a status_detail saying why. The evaluator checks in this order and stops at the first match:

    1. "invalid": the parser raises an ExpressionParseError.
    2. "rejected": a pre-check of a required constraint fails (see below), so the expression is not scored; or the ranking function rejects it while scoring.
    3. "error": the ranking function, or a check of a required constraint, raises. The evaluator also emits a warning.
    4. "undefined": the ranking function returns a non-finite error.
    5. "rejected": a post-check of a required constraint fails. The fit is kept in parameters.
    6. "ok": otherwise.

    Every status except "ok" gets the error +inf, so an evaluated expression never gives NaN and failed models rank after every scored one. Every call counts toward max_evaluations, whatever its status. Once evaluation has stopped (threshold or budget reached), further calls are not evaluated: they warn, return nan and are not counted.

    The statuses are saved with the results, so validity can be measured after the run from status_counts. Count every well-formed expression as valid, including rejected and undefined ones, and leave "error" out entirely, because those failures belong to the evaluation, not to the approach:

    counts = result.status_counts()  # per unique expression; per="call" counts every call
validity_rate = 1 - counts["invalid"] / (sum(counts.values()) - counts["error"])

    Constraints

    The evaluator enforces the required_constraints and records the advisory ones, which are the constraints of its background knowledge (see below). Both are ExpressionConstraints; that module explains what the checks look at and the two roles. The evaluator calls setup with its symbol library on its own copies, so the instances passed in are not changed.

    • required_constraints: pre-checks run in order after parsing, post-checks in order after an "ok" score. The first failure gives "rejected" with the status_detail "<ClassName>: <message>", e.g. "MaxConstants: 9 constants, limit 8", and the later checks of that stage are not run. The settings max_constants (default 8) and max_expr_length add a MaxConstants and a MaxTokens in front of the list, unless a negative setting disables them or the list already has one of that class (see SR_evaluator), so [] still allows at most 8 constants.
    • advisory_constraints: pre-checks run on every parsed expression, post-checks on every "ok" model. Each failed check is recorded in ModelResult.advisory_violations as a CheckResult with constraint and stage filled in; the error is not affected.

    For one expression the order is: parse, advisory pre-checks, required pre-checks, score, required post-checks, advisory post-checks. So rejected models and models with status "error" still carry their advisory pre-check results. Pre-checks get ModelResult.expr (simplified if simplify_expr=True), post-checks the ModelResult. Checks a constraint does not implement are skipped.

    A check that raises an exception, or returns something other than a CheckResult (treated as a TypeError), emits a UserWarning and counts as failed, with CheckResult.error set to "<ExceptionType>: <message>". For a required constraint the status is then "error" with the status_detail "<ClassName>.<pre_check|post_check> raised <ExceptionType>: <message>". For an advisory constraint the result is recorded in advisory_violations like any failed check; leave results with error set out when counting violations.

    To avoid spending evaluations on expressions that would fail a pre-check, or to filter candidates by the advisory constraints, an approach can call check_constraints first: it runs the pre-checks only and is not billed.

    Background knowledge

    The search sees only the evaluator, so the evaluator carries the task's BackgroundKnowledge as background_knowledge. describe and priors give the task as text and as records, the same as the dataset's, e.g. to build an LLM prompt. Neither mentions the answer, but the evaluator does not hide it: ground_truth is a public attribute, which an approach must not read.

    Evaluation trace

    The evaluator records every counted call to evaluate_expr in order, and each EvalResult carries this record as trace: trace[k] is the index into all_models of the expression requested by call k + 1. Cache hits appear as repeated indices, since they count toward max_evaluations; calls made after evaluation stopped are not recorded. Three methods derive the usual fixed-target and fixed-budget quantities from it:

    • best_so_far: the calls at which the best error strictly improved;
    • calls_to_threshold: the number of calls needed to first reach an error below a threshold (success_threshold by default), or None;
    • best_error_within: the best error within each of the given numbers of calls.

    A run that never reaches the threshold is censored, not missing: it shows that more than evaluation_calls calls were needed. Keep such runs when aggregating, for example as the fraction of runs solved within each budget:

    import numpy as np
from SRToolkit.experiments import ExperimentGrid

grid = ExperimentGrid.load("results/grid.json")
results = grid.load_results("Nguyen-1", "ProGED")

budgets = np.array([100, 1_000, 10_000])  # at most the experiment's max_evaluations
needed = [r.calls_to_threshold() for r in results]
solved = [np.mean([n is not None and n <= b for n in needed]) for b in budgets]

curves = np.stack([r.best_error_within(budgets) for r in results])
median_curve = np.nanmedian(curves, axis=0)

    A result does not record max_evaluations or why its search stopped. For a run that stopped early for another reason than reaching the threshold (e.g. a time limit), best_error_within past its last call is only an upper bound, and a None from calls_to_threshold is censored at fewer calls than the budget. If your runs can stop early, check evaluation_calls against the budget before comparing approaches.

>>> se = SR_evaluator(X, y)

>>> print(rmse < 1e-6)

    evaluate_expr 

    evaluate_expr(expr: Union[List[str], Node], simplify_expr: bool = False, verbose: int = 0) -> float

    Evaluate an expression, or return its cached error.

    A new expression is parsed, checked against the constraints, scored by the ranking function and stored in models (statuses and the order of checks are in the module docs). An expression evaluated before is not scored again; its stored error is returned. Either way the call is appended to trace, counts toward max_evaluations and is reported to the callbacks: on_expr_evaluated for every call, plus on_best_expression when the error improves on the best so far. A callback returning False stops evaluation; by default this happens when an error is below success_threshold or max_evaluations is reached.

    Note

    simplify_expr=True makes a call much slower: simplifying with SymPy usually takes longer than scoring the expression. Use it to inspect the best results after a search, not on every candidate during it.

    Examples:

    >>> X = np.array([[1, 2], [8, 4], [5, 4], [7, 9]])
>>> y = np.array([3, 0, 3, 11])
>>> se = SR_evaluator(X, y, seed=42)
>>> print(se.evaluate_expr(["C", "*", "X_1", "-", "X_0"]) < 1e-6)
True
>>> # With simplify_expr, the simplified expression is scored and stored
>>> X = np.array([[0, 1], [0, 2], [0, 3]])
>>> se = SR_evaluator(X, np.array([2, 3, 4]), seed=42, success_threshold=-1)
>>> _ = se.evaluate_expr(["C", "+", "C", "*", "C", "+", "X_0", "*", "X_1", "/", "X_0"], simplify_expr=True)
>>> "".join(se.models[0].expr), bool(0.99 < se.models[0].parameters[0] < 1.01)

    def evaluate_expr(
    self,
    expr: Union[List[str], Node],
    simplify_expr: bool = False,
    verbose: int = 0,
) -> float:
    """Evaluate an expression, or return its cached error.

    A new expression is parsed, checked against the constraints, scored by the ranking
    function and stored in ``models`` (statuses and the order of checks are in the
    [module docs][SRToolkit.evaluation.sr_evaluator]). An expression evaluated before is not
    scored again; its stored error is returned. Either way the call is appended to ``trace``,
    counts toward ``max_evaluations`` and is reported to the callbacks: ``on_expr_evaluated``
    for every call, plus ``on_best_expression`` when the error improves on the best so far. A
    callback returning ``False`` stops evaluation; by default this happens when an error is
    below ``success_threshold`` or ``max_evaluations`` is reached.

    Note:
        ``simplify_expr=True`` makes a call much slower: simplifying with SymPy usually takes
        longer than scoring the expression. Use it to inspect the best results after a search,
        not on every candidate during it.

    Examples:
        >>> X = np.array([[1, 2], [8, 4], [5, 4], [7, 9]])
        >>> y = np.array([3, 0, 3, 11])
        >>> se = SR_evaluator(X, y, seed=42)
        >>> print(se.evaluate_expr(["C", "*", "X_1", "-", "X_0"]) < 1e-6)
        True
        >>> # With simplify_expr, the simplified expression is scored and stored
        >>> X = np.array([[0, 1], [0, 2], [0, 3]])
        >>> se = SR_evaluator(X, np.array([2, 3, 4]), seed=42, success_threshold=-1)
        >>> _ = se.evaluate_expr(["C", "+", "C", "*", "C", "+", "X_0", "*", "X_1", "/", "X_0"], simplify_expr=True)
        >>> "".join(se.models[0].expr), bool(0.99 < se.models[0].parameters[0] < 1.01)
        ('C+X_1', True)
        >>> # A malformed expression gets the error inf and the status "invalid"
        >>> print(se.evaluate_expr(["C", "*", "X_1", "X_0"]))
        inf
        >>> se.models[-1].status
        'invalid'
        >>> # BED is stochastic and scaled by the ground truth's output, so an exact match may
        >>> # still have a small positive error
        >>> X = np.random.rand(10, 2) - 0.5
        >>> se = SR_evaluator(X, ground_truth=["X_0", "+", "C"], ranking_function="bed", seed=42)
        >>> print(se.evaluate_expr(["C", "+", "X_0"]) < 0.2)
        True

    Args:
        expr: The expression, as a token list in infix notation or a
            [Node][SRToolkit.utils.expression_tree.Node] tree.
        simplify_expr: If ``True``, simplify the expression first; the simplified
            expression is then checked, scored, cached and stored as ``ModelResult.expr``, so
            inputs that simplify alike share one cache entry. If simplification fails, a
            warning is emitted and the expression is evaluated as given. Default ``False``.
        verbose: ``0`` (default): no logging. ``1``: log at DEBUG level (logger
            ``SRToolkit.evaluation.sr_evaluator``) each new expression with its final status,
            error and ``status_detail``, and each cache hit. ``2``: also let NumPy
            floating-point warnings through while scoring.

    Returns:
        The error under the active ranking function, or ``+inf`` if the status is not
        ``"ok"``. ``nan`` if evaluation has already stopped: the call then emits a warning and
        is not counted.

    Raises:
        TypeError: If ``expr`` is neither a token list nor a ``Node``.
    """
    if self.should_stop:
        warnings.warn(
            f"Evaluation stopped because max_evaluations ({self.max_evaluations}) reached or an expression with error lower than success_threshold ({self.success_threshold}) was found. "
        )
        return np.nan
    else:
        if simplify_expr:
            try:
                expr = simplify(expr, self.symbol_library)
            except Exception as e:
                expr_list = _as_tokens(expr, self.symbol_library)
                warnings.warn(f"Unable to simplify: {''.join(expr_list)}, problems with subexpression {e}")

        expr_list = _as_tokens(expr, self.symbol_library)

        expr_str = "".join(expr_list)
        index = self._model_index.get(expr_str)
        if index is not None:
            if verbose > 0:
                logger.debug("Already evaluated %s", expr_str)
            self.trace.append(index)
            if self._callbacks is not None:
                event = ExprEvaluated(
                    expression=expr_str,
                    error=self.models[index].error,
                    evaluation_number=self.total_evaluations,
                    experiment_id=self._experiment_id,
                    is_new_best=False,
                    status=self.models[index].status,
                )
                if not self._callbacks.on_expr_evaluated(event):
                    self.should_stop = True
            return self.models[index].error

        else:
            model = self._evaluate_new(expr, expr_list, expr_str, verbose)
            if verbose > 0:
                logger.debug(
                    "Evaluated expression %s: status %s, error %s%s",
                    expr_str,
                    model.status,
                    model.error,
                    f" ({model.status_detail})" if model.status_detail else "",
                )
            error = model.error
            self._model_index[expr_str] = len(self.models)
            self.trace.append(len(self.models))
            self.models.append(model)

            if self._callbacks is not None:
                is_new_best = error < self._current_best_error
                if is_new_best:
                    self._current_best_error = error
                event = ExprEvaluated(
                    expression=expr_str,
                    error=error,
                    evaluation_number=self.total_evaluations,
                    experiment_id=self._experiment_id,
                    is_new_best=is_new_best,
                    status=model.status,
                )
                if not self._callbacks.on_expr_evaluated(event):
                    self.should_stop = True
                if is_new_best:
                    best_event = BestExpressionFound(
                        experiment_id=self._experiment_id,
                        expression=expr_str,
                        error=error,
                        evaluation_number=self.total_evaluations,
                    )
                    if not self._callbacks.on_best_expression(best_event):
                        self.should_stop = True

            return error

            [REGRESSION_METRICS][SRToolkit.utils.measures.REGRESSION_METRICS]
            (``"mse"``, ``"rmse"``, ``"mae"``, ``"r2"``, ``"nrmse"``), or a callable with the
            signature ``metric(predict, X, y) -> float`` where ``predict(X) -> y_pred``
            has the fitted constants bound in. Default ``"r2"``.

    def evaluate_metric(
    expr: Union[List[str], Node],
    parameters: Optional[np.ndarray],
    X: np.ndarray,
    y: np.ndarray,
    metric: Union[str, Callable[[Callable[[np.ndarray], np.ndarray], np.ndarray, np.ndarray], float]] = "r2",
    symbol_library: Optional[SymbolLibrary] = None,
    backend: str = "stack",
) -> float:
    """Score an expression on ``(X, y)`` by reusing already-fitted ``parameters`` — no refitting.

    Builds a constants-bound prediction function ``predict(X) -> y_pred`` from ``expr`` and
    ``parameters`` and applies ``metric``. This is the shared scoring core behind
    [SR_evaluator.get_metric][SRToolkit.evaluation.sr_evaluator.SR_evaluator.get_metric] (train
    data) and [HoldoutMetric][SRToolkit.evaluation.result_augmentation.HoldoutMetric] (held-out
    data) — the same call against different arrays.

    Args:
        expr: Expression as an infix token list or a [Node][SRToolkit.utils.expression_tree.Node].
        parameters: Fitted constants to bind in. ``None`` is treated as an empty array.
        X: Inputs of shape ``(n_samples, n_features)`` to score on.
        y: Targets of shape ``(n_samples,)`` to score against.
        metric: A built-in name in
            [REGRESSION_METRICS][SRToolkit.utils.measures.REGRESSION_METRICS]
            (``"mse"``, ``"rmse"``, ``"mae"``, ``"r2"``, ``"nrmse"``) or a callable
            ``metric(predict, X, y) -> float``.
        symbol_library: Symbol library used to compile ``expr``. Defaults to the package default.
        backend: Compilation backend forwarded to
            [compile_expr][SRToolkit.utils.expression_compiler.compile_expr]. Default ``"stack"``.

    Returns:
        The metric value as a float, or ``NaN`` if the metric raises during computation.

    Raises:
        ValueError: If ``metric`` is a string that is not a known built-in metric.
        TypeError: If ``metric`` is neither a string nor a callable.
    """
    if isinstance(metric, str):
        if metric not in REGRESSION_METRICS:
            raise ValueError(
                f"[evaluate_metric] Unknown metric '{metric}'. Available built-in metrics: "
                f"{sorted(REGRESSION_METRICS)}. Alternatively pass a callable with signature "
                "metric(predict, X, y) -> float."
            )
        metric_fn = REGRESSION_METRICS[metric]
    elif callable(metric):
        metric_fn = metric
    else:
        raise TypeError(f"[evaluate_metric] metric must be a string or a callable, got {type(metric).__name__}.")

    expr_list = _as_tokens(expr, symbol_library)

    raw = compile_expr(expr_list, symbol_library, backend=backend)
    params = parameters if parameters is not None else np.array([])

    def predict(X_in: np.ndarray) -> np.ndarray:
        return raw(X_in, params)

    try:
        with np.errstate(divide="ignore", invalid="ignore", over="ignore", under="ignore"):
            return float(metric_fn(predict, X, y))
    except Exception as e:
        warnings.warn(f"[evaluate_metric] Error computing metric for '{''.join(expr_list)}': {e}")
        return float("nan")
